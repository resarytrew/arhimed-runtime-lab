# ManimGX 0.1.1 browser-sandbox experiment

Status: **negative for configuration 1; Stage 1 is not accepted.**

Public lab: <https://resarytrew.github.io/arhimed-runtime-lab/>  
Source commit: `bbb150e3fd566b7a47fcb65c0af40752f09de445`  
Successful Pages workflow: <https://github.com/resarytrew/arhimed-runtime-lab/actions/runs/38596223556>

This lab deliberately contains synthetic parent control strings only. The parent puts separate values in its DOM, `localStorage`, and IndexedDB. The sandbox runs as `<iframe sandbox="allow-scripts">`, without `allow-same-origin`, and receives commands only through a versioned message schema, iframe-window identity, a per-load random capability, monotonic revision, and a 16 KiB source cap.

## Tested configuration

The child CSP allows only the hosted application bundle, `blob:` code generated by the pinned runtime, the exact Pyodide CDN origin, and the exact pinned ManimGX wheel origin. It denies arbitrary egress, forms, base changes, objects, media, and navigation privileges. The parent CSP allows no network connection.

The real `manimgx@0.1.1` custom element was used. It starts a module Worker from a Blob URL. In the opaque-origin iframe, classic Blob Workers run but Blob **module** Workers do not start. ManimGX consequently reports `ManimGX could not start: undefined` before it requests Pyodide or the wheel.

This is a useful negative result: enabling `allow-same-origin` would change the isolation boundary, so the lab does not do that and Studio must not integrate this configuration.

Observed CSP console events record denied connection attempts to `http://127.0.0.1:9/` and `https://example.invalid/`. The Worker probe separately confirms that CSP keeps blocking egress inside a classic Worker. The browser’s `navigator.gpu` presence is recorded as capability information only and is not treated as a rendering success.

The following requirements remain intentionally unclaimed: WebGPU rendering, first-frame p95, GPU-loss recovery, memory-limit enforcement, and a compatible isolated ManimGX runtime. Browser processes cannot provide a hard shared RAM/GPU limit; terminating the Worker/context remains the proposed cancellation primitive once a compatible configuration exists.

## Required alternative before further integration

The second configuration needs a separately administered HTTPS origin for the runtime and a parent origin which cannot read it, with a strict CSP and a sandbox policy assessed again on real browsers. Different paths under `resarytrew.github.io` are the same origin and are therefore not suitable. A dedicated `runtime.arhimed.studio` origin or a separately owned GitHub Pages origin is required. Until one is provisioned and passes an equivalent test suite, ManimGX stays out of `ArhimedStudio` and published lectures use Canvas or prepared video fallback.
